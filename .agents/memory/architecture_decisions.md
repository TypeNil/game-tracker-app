# Architecture Decision Records (ADR) — GameTracker

## ADR-001: Модульность и разделение границ пакетов
- **Контекст**: Проект начинается в едином модуле `:app`, но планируется к разделению на `:core:*` и `:feature:*`.
- **Решение**: Организовать внутреннюю структуру пакетов в `:app` строго по слоям и фичам: `core/model`, `core/database`, `core/network`, `core/data`, `core/designsystem`, `feature/<feature_name>`.
- **Последствия**: Никаких циклических зависимостей; миграция на Gradle multi-module в будущем сводится к механическому переносу директорий в отдельные модули без переписывания архитектуры.

## ADR-002: Backend for Frontend (BFF) на Kotlin/Ktor
- **Контекст**: IGDB API использует закрытый OAuth2 и тяжелые ответы. Хранение секретов на клиенте небезопасно.
- **Решение**: Разместить легковесный Ktor-сервис в `./backend`, выступающий прокси-шлюзом к IGDB.
- **Последствия**: Мобильное приложение общается только с BFF или работает в `demo` режиме через встроенные фикстуры.

## ADR-003: Build Flavors (`demo` vs `live`)
- **Контекст**: Необходимость тестирования и демонстрации приложения без поднятия локального бэкенда.
- **Решение**: Ввести `flavorDimensions += "environment"` с вариантами `demo` (встроенный `FakeRemoteDataSource`) и `live` (Retrofit HTTP клиент к BFF).
- **Последствия**: Идеально для демонстрации проекта на GitHub (APK `demoRelease` запускается сразу).

## ADR-004: UDF и Single Source of Truth (SSOT) через Room
- **Контекст**: Пользовательская библиотека и кеш каталога должны быть доступны оффлайн и реактивно обновлять экран.
- **Решение**: Репозиторий сохраняет полученные данные из сети в базу данных Room, а UI подписывается на `Flow<List<Entity>>` из Room через `ViewModel`.
- **Последствия**: UI всегда консистентен, нет рассинхронизации между локальным состоянием и экраном.

## ADR-005: Jetpack Compose, Material 3 и Strong Skipping Mode
- **Контекст**: Разработка нативного UI с максимальной производительностью в 2026 году.
- **Решение**: Использовать Kotlin 2.2+ Compose Compiler, Material 3, immutable state models и стабильные ключи в списках (`items(..., key = { it.id })`).
