# Алгоритм рекомендаций в GameTracker

Техническое описание нативного эвристического рекомендательного движка GameTracker, функционирующего на устройстве без отправки телеметрии на внешние серверы.

---

## 1. Концепция и архитектурные цели

Большинство рекомендательных систем в современных приложениях работают как облачные «чёрные ящики» на основе сложных нейросетевых моделей, требующих сбора детализированной пользовательской телеметрии и постоянной связи с сервером.

В GameTracker реализован **детерминированный нативный движок** (`core/model`):
- **100% On-Device**: Все вычисления производятся локально на процессоре смартфона в фоновом потоке (`@DefaultDispatcher`).
- **Полная приватность**: Пользовательские оценки, статусы библиотеки и список любимых игр никогда не покидают устройство.
- **Интерпретируемость (Explainability)**: Каждая рекомендация имеет прозрачное математическое обоснование, которое транслируется пользователю в виде понятных причин в карточке игры.

---

## 2. Сбор сигналов (`RecommendationProfileBuilder`)

Входными данными для построения профиля служат записи локальной библиотеки пользователя (`RecommendationSignal`). Для каждой игры рассчитывается результирующая дельта предпочтения $\Delta$:

| Библиотечный сигнал | Условие в коде | Дельта $\Delta$ |
| :--- | :--- | :--- |
| **Избранное** | `isFavorite == true` | `+3.0` |
| **В процессе игры** | `status == PLAYING` | `+2.0` |
| **Пройдено** | `status == COMPLETED` | `+2.0` |
| **В планах** | `status == WISHLIST` | `+1.0` |
| **Высокая оценка** | `rating in 7..10` | Дополнительный бонус: `+(rating - 6)` (от `+1.0` за 7 до `+4.0` за 10) |
| **Не интересно** | `status == NOT_INTERESTED` | `-2.0` (негативный сигнал) |
| **Брошено** | `status == DROPPED && rating <= 4` | `-2.0` (негативный сигнал) |

### Агрегация и нормализация осей
Полученные дельты проецируются на три ортогональные оси характеристик:
1. **Жанры (`genres`)**
2. **Темы (`themes`)**
3. **Платформы (`platforms`)** *(применяется фильтр доминирующих платформ: минимум 3 позитивные игры и доля $\ge 50\%$)*

Для каждой оси суммируются положительные и отрицательные веса, после чего вектор нормализуется делением на максимальный по модулю элемент:
$$w_{\text{norm}} = \frac{w}{\max(|w_{\min}|, |w_{\max}|)} \in [-1.0, 1.0]$$

## 3. Скоринг и ранжирование кандидатов (`RecommendationRanker`)

Кандидатами на рекомендацию выступают игры из каталога Discover, которых ещё нет в библиотеке пользователя. Кандидат оценивается взвешенной формулой:

$$\text{Score} = (W_g \cdot \text{genreOverlap}) + (W_t \cdot \text{themeOverlap}) + (W_p \cdot \text{platformOverlap}) + (W_s \cdot \text{similarBoost}) + (W_r \cdot \text{bayesianRating}) + (W_n \cdot \text{negativePenalty})$$

### Весовые коэффициенты (`RankerWeights`):

| Фактор | Вес в коде | Описание вычисления |
| :--- | :---: | :--- |
| **Genre Overlap** | `1.0` | Скалярное произведение нормализованного вектора жанров профиля и жанров игры. |
| **Theme Overlap** | `0.8` | Скалярное произведение вектора тем профиля и тем игры. |
| **Platform Overlap** | `0.5` | Соответствие целевых платформ кандидата предпочтительным платформам пользователя. |
| **Similar Boost** | `1.5` | Бонус, если кандидат связан связью «похожая игра» с сид-играми из библиотеки пользователя (игры со статусами `Favorite`, `Playing`, `Completed` или `Wishlist`). |
| **Bayesian Rating** | `0.4` | Сглаженный глобальный рейтинг критиков и игроков. |
| **Negative Penalty**| `1.0` | Весовой коэффициент равен `1.0`. Сам фактор штрафа вычисляется как сумма отрицательных перекрытий жанров, тем и платформ профиля и всегда неположителен ($\text{negativePenalty} \le 0$). |
| **Recency** | `0.0` | Резервный фактор даты релиза (в текущей версии отключён для стабильности рекомендаций). |

### Байесовское сглаживание рейтинга (Bayesian Average)
Для предотвращения перекосов, когда малоизвестная игра с одним случайным отзывом 100/100 выходит в топ:
$$\text{Bayesian} = \frac{v \cdot R + M \cdot C}{v + M} \cdot \frac{1}{100}$$
где:
- $R$ — средний рейтинг игры по версии IGDB;
- $v$ — количество голосов;
- $M = 10$ — минимально необходимый порог голосов (вес априорного знания);
- $C = 70.0$ — априорное математическое ожидание рейтинга для всей индустрии видеоигр.

## 4. Формирование объяснений (`RecommendationExplainer`)

Для формирования доверия пользователя интерфейс не просто показывает список игр, а снабжает каждую рекомендацию объясняющими плашками:

1. Движок рассчитывает реальный вклад каждого фактора в итоговый скор:
   $$\text{Contribution}_i = \text{Weight}_i \times \text{FactorValue}_i$$
2. Отбираются **до 2 факторов** с максимальным положительным вкладом.
3. Факторы преобразуются в локализованные причины `RecommendationReason`:
   - **Совпадение жанра**: *«Совпадение по жанру: RPG»*
   - **Совпадение темы**: *«Совпадение по теме: Научная фантастика»*
   - **Совпадение платформы**: *«Доступно на вашей платформе: PC»*
   - **Связь с библиотекой**: *«Похоже на игры из вашей библиотеки»*
   - **Высокая оценка**: *«Высокая оценка игроков»*

---

## 5. Границы и ограничения алгоритма

1. **Холодный старт (Cold Start)**: При отсутствии положительных сигналов в библиотеке профиль помечается флагом `isColdStart`. Внутренний API билдера поддерживает параметры `coldStartGenres` и `coldStartPlatforms` для первичного онбординга, однако в текущей версии приложения явный UI-диалог выбора стартовых предпочтений к `DiscoverViewModel` не подключён — при пустой библиотеке пользователю предлагается добавить первые игры.
2. **Пул кандидатов**: Вычисления производятся детерминированно над кэшированным пулом игр ленты Discover в фоновом пуле корутин (`Dispatchers.Default`), гарантируя отзывчивость интерфейса без блокировки основного UI-потока.
